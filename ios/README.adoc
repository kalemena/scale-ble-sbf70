= SBF70 iOS App
:toc: left
:toclevels: 3
:sectanchors:
:icons: font
:source-highlighter: rouge

Native SwiftUI iPhone app that talks directly to the *Sanitas SBF70* body scale
(and the same Beurer/Sanitas family: Beurer BF710, Silvercrest SBF75, Crane
`AICDSCALE1`) over Bluetooth Low Energy.

It is a Swift/CoreBluetooth port of the Python CLI in
`../tools/sbf70-cli/sbf70.py`: same GATT service (`0xFFE0`), characteristic
(`0xFFE1`), start byte (`0xE7`), opcodes, and frame layouts, so the two stay
cross-referenceable. The app's JSON output uses the same keys as the CLI, so
exports feed straight into `../tools/measurements-report.py`.

See `plan.md` for the full design, protocol reference, and implementation
checklist.

[NOTE]
====
The scale sleeps aggressively. *Wake it* (step on it briefly) so it advertises,
then scan from the app within ~15 seconds.
====

== Features (v1)

* *Sync* saved history from the scale
* *History* list with Swift Charts (weight line + fat/water/muscle overlays)
* *Live measurement* mode
* *User management* on the scale — list / details / add (experimental) / delete

=== Architecture

* *`ScaleTransport`* protocol isolates CoreBluetooth. `SBF70Client` consumes an
  `AsyncStream<[UInt8]>` of notifications plus a `write(_:)`; it never touches
  CoreBluetooth directly, which keeps the protocol logic unit-testable with a
  mock transport.
* *`CoreBluetoothTransport`* is the only CoreBluetooth-aware type (plus
  `ScaleScanner` for discovery).
* *`SBF70Client`* is an `actor`: it owns the notification queue and implements
  the `wait(predicate:timeout:autoAck:)` + auto-ACK pattern ported from the CLI.
* *One session at a time* — `SessionViewModel` holds a single connected client
  shared by every screen and runs the INIT / SET_TIME handshake on connect.
* *Storage* is plain JSON under `Documents/Sbf70/` via the `JsonStore` actor,
  using CLI-compatible keys.

== Requirements

* macOS with *Xcode 17 or later* (full Xcode, not just Command Line Tools)
* iOS *17+* deployment target
* A physical *iPhone* for BLE testing — the iOS Simulator has no Bluetooth
* https://github.com/yonaskolb/XcodeGen[XcodeGen] to generate the app project
  (`make setup` installs it via Homebrew)

[NOTE]
====
The `Sbf70Kit` package (logic, protocol, storage) builds and tests with the
Swift toolchain alone — no Xcode project generation needed. Only the SwiftUI
*app* target needs `xcodebuild` and a generated `.xcodeproj`.
====

== Quick start

[source,bash]
----
cd ios

make setup        # install XcodeGen (if needed) + generate the Xcode project
make smoke        # fast no-Xcode protocol sanity checks
make build        # build the app for the iOS Simulator
make open         # open the project in Xcode
----

To install a *Release* build on your own iPhone over a cable (no App Store, no
paid Developer Program — a free Apple ID works):

[source,bash]
----
make devices                               # list cabled iPhones + their UDIDs
make install DEVELOPMENT_TEAM=ABCDE12345   # build + sign + install over cable
----

See <<install-on-your-iphone>> for the full walkthrough and caveats.

[[install-on-your-iphone]]
== Install a Release build on your iPhone (no App Store)

You can run a *Release* (optimized) build on your own device without the App
Store and without the paid Apple Developer Program. A *free Apple ID* is enough
for personal-device installs.

=== One-time setup

. Sign into your Apple ID in *Xcode → Settings → Accounts*. Xcode then manages a
  free "Personal Team" signing certificate and provisioning profiles for you.
. Note your *Team ID* (10 characters, e.g. `ABCDE12345`) — shown next to your
  team in that Accounts pane, or at developer.apple.com → Membership.
. Plug the iPhone into this Mac with a cable and *trust* the computer when the
  phone prompts.

=== Build + sign + install

[source,bash]
----
make devices                               # confirm the phone shows up, grab its UDID
make install DEVELOPMENT_TEAM=ABCDE12345   # Release archive -> signed .ipa -> install
----

`install` runs `archive` (Release config, automatic signing with your Team ID,
`-allowProvisioningUpdates` so Xcode mints the profile) → `ipa`
(`method=development` export) → `xcrun devicectl device install app` over the
cable. If more than one device is attached, pass the target explicitly:

[source,bash]
----
make install DEVELOPMENT_TEAM=ABCDE12345 DEVICE_UDID=00008110-0001...
----

=== First launch: trust the developer

After installing, the app won't open until you trust the signing identity on the
phone: *Settings → General → VPN & Device Management →* your developer Apple ID
*→ Trust*.

[IMPORTANT]
====
*Free Apple ID signing expires after ~7 days.* The app stops launching once the
profile lapses — just re-run `make install` to re-sign and reinstall.
====

== Permissions

The app requests *Bluetooth* via `NSBluetoothAlwaysUsageDescription` (set in
`project.yml` → generated into the app's `Info.plist`). On first launch iOS
prompts for Bluetooth access; without it, scanning and connecting fail. You can
re-enable it later under *Settings → Privacy & Security → Bluetooth*.

CoreBluetooth peripheral identifiers on iOS are per-device UUIDs, not MAC
addresses. The app persists the last peripheral UUID so it can offer to
reconnect; a "forget device / rescan" path lives in Settings if the UUID goes
stale.

== Wake-and-connect workflow

1. *Wake the scale* — step on it briefly so it starts advertising.
2. Open the app and *scan* within ~15 seconds; the scanner filters on the same
   name hints as the CLI (`SANITAS SBF70`, `SBF75`, `AICDSCALE1`, `BEURER
   BF710` / `BF700`…).
3. *Connect* — the app discovers `FFE0`/`FFE1`, subscribes to notifications, and
   runs the INIT / SET_TIME handshake.
4. Use *Sync*, *Live*, or *Users*. Each batch re-runs the session init, because
   the scale silently drops a lapsed session (the command just times out).
5. Disconnect is graceful (`EA 02`); the app also disconnects when backgrounded.

[NOTE]
====
Body composition (fat / water / muscle / impedance) is only produced for a user
*registered on the scale*. For an unregistered user the live measurement returns
weight only. Create a profile on the scale (or via the experimental add-user
screen) first.
====

== Relationship to the CLI

* Same protocol constants and frame layouts as `../tools/sbf70-cli/sbf70.py` —
  opcode and method names are kept identical for cross-reference.
* Same JSON schema (`timestamp`, `time_iso`, `weight_kg`, `impedance`,
  `fat_pct`, `water_pct`, `muscle_pct`, `bone_kg`, `uid`), so:
** App history exports can be analysed with `../tools/measurements-report.py`.
** A `sbf70.py history` JSON export can be *imported* into the app (Settings →
   Import) to seed the UI without a scale — handy for development.

== Testing

[source,bash]
----
make smoke      # protocol/codec/store checks, no Xcode project required
make kit-test   # full XCTest suite (via SPM)
----

The smoke runner (`Sources/sbf70-smoke`) mirrors the critical XCTest cases —
codec round-trips, INIT/status/users/history/live flows against a mock
transport, ACK-byte assertions, and `JsonStore` merge/dedupe — so the protocol
layer can be verified on a machine without the full Xcode app build.

== Troubleshooting

[cols="1,2", options="header"]
|===
| Symptom | Fix

| Nothing found when scanning
| Wake the scale (step on it) and rescan within ~15 s. Another app
  (HealthCoach, openScale) may be holding the connection.

| Commands time out after connecting
| The session lapsed — reconnect, or let the app re-init (Sync/Users/Live do
  this automatically).

| Live measure returns weight but no body composition
| The user is not registered on the scale, or impedance arrived late. Stand
  still a few more seconds after the weight stabilises, then retry.

| `xcodegen not found`
| Run `make setup` (installs via Homebrew), or install manually from the
  XcodeGen repo.

| `CoreSimulator is out of date`
| Update macOS / Xcode, or build/archive for a device (`make build-device`)
  instead of the simulator.

| `overlapping sources: Sbf70KitTests`
| The `Tests/Sbf70KitTests/` directory is missing — see the Testing note above.
|===
